## Confirmed discrepancies and material omissions

1. **High — The “closest prior systems” comparison omits two already checked, decision-relevant predecessors.** `docs/chapters/02-literature-review.tex:32–58` presents the table as the closest mechanisms, but it omits Spectroscope and Shahedi et al. The [Monitoring Novelty Cross Reference](../../task%201/Research%20Management/Monitoring%20Novelty%20Cross%20Reference.md) identifies Spectroscope (abstract and §§3, 8.1) as performance-change diagnosis from healthy/problem request flows, while [Source Appraisals SC-C04](../../task%201/Research%20Archive/Review%20Artifacts/2026-10-31%20Decision-Critical%20Source%20Checks/Source%20Appraisals.md) establishes Shahedi's selective tracepoint/regression-detection precedent from **arXiv v1 (2024)**. Both have bibliography keys (`Z2BQ69Z4`, `IX2DU87B`). Add concise rows or a source-backed paragraph that states the overlap and exact non-equivalence: Spectroscope uses observed distributed request-flow evidence; Shahedi studies native function tracing across versions/inputs, not original-cause recovery from a later browser visit. Argus (`KE53ZLW3`) is a narrower, introduction/§2-only related-work lead with a Chrome/macOS responsiveness example; mention it as a bounded lead if claiming browser diagnosis as established, without implying its evaluation has been appraised. This strengthens the gap argument without claiming that no exact equivalent exists.

2. **Medium — The synthesis says ingredients exist “separately,” although cited systems already combine several.** `docs/chapters/02-literature-review.tex:73`: “The literature establishes each broad ingredient separately.” LMAT combines deviation-driven monitoring and richer tracing; Hindsight combines continuous capture, bounded retention and triggered retrieval; Vesper combines discovery and a second measurement pass. The table and [Source Appraisals SC-C01, C02, C07](../../task%201/Research%20Archive/Review%20Artifacts/2026-10-31%20Decision-Critical%20Source%20Checks/Source%20Appraisals.md) establish these combinations. Replace “separately” with wording such as “Existing work establishes these mechanisms and several combinations of them.” Preserve the actual proposed gap: a matched-budget, independently labelled comparison of original-episode cause attribution using original-visit versus later-visit browser evidence.

3. **Medium — Budget language can make the always-rich reference look budget-matched.** `docs/chapters/01-introduction.tex:16` says the report will “compare complete strategies under a common monitoring budget and diagnosis deadline,” and `docs/frontmatter/abstract.tex:3` lists an “always-rich reference” among the comparisons. The [Research Plan, Objective 3](../../task%201/Research%20Management/Research%20Plan.md) assigns arm E a **separate resource allowance** and treats it as a coverage/cost reference, not a guaranteed upper bound or matched-budget arm. Name B/C and the other budget-comparable policies as the principal comparison; explicitly identify always-rich as a separately costed reference in the abstract or first strategy description.

4. **Medium — The metric-definition citations are traceable by key but not by edition in the submission bibliography.** `docs/chapters/02-literature-review.tex:8–10` claims to use “inspected, version-bound metric documentation”; the cited BibLaTeX entries for LCP (`6WVYFE8R`), Paint Timing (`84ZFNR74`), Navigation Timing (`JJWRMF5Z`), Performance Timeline (`REP5RHB6`), and mutable web.dev guidance give retrieval dates but usually omit the specification's draft date/status or a release identifier. The local source notes and [literature matrix](../../task%201/Research%20Management/Literature%20Review%20and%20Research%20Gap%20Matrix.md) record these dates (for example, LCP Working Draft 26 Aug 2026; Paint Timing Working Draft 2 Oct 2026; Navigation Timing Level 2 Working Draft 1 Sep 2026; Performance Timeline Candidate Recommendation Draft 21 May 2025). Add inspected edition/date/status to bibliography entries or a compact source-to-claim ledger. Keep WICG Layout Instability API distinct from Google's final CLS session-window algorithm and keep `web-vitals` v5.1.0 as a **reference documentation release**, not the selected runtime.

5. **Low — The TTFB citation set includes Resource Timing without explaining the navigation formula.** `docs/chapters/02-literature-review.tex:10` correctly says client-observed TTFB is not server CPU time, but the cited `JJWRMF5Z,NXHCE5SV` mix navigation and per-resource timing.
