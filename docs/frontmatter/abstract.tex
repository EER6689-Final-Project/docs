\ReportFrontChapter{Abstract}

A website monitor can report a slow visit without retaining enough information to explain it. If an analyst then records a detailed browser profile, the cause may have disappeared: for example, a delayed image response may have recovered before the second visit. A profile of that second visit may be accurate but still give the wrong explanation for the first. This report proposes a controlled study of how reliably delayed profiling identifies the cause of an earlier website performance regression.

The study will compare detailed follow-up profiles with evidence retained from the original visit under matched monitoring budgets and a shared diagnosis deadline. Scheduled visits to controlled test websites will include faults that persist, disappear or are replaced by another cause. Independent checks will establish which fault was active on each visit. The main outcome will be correct attribution of the original cause for intermittent faults; missed alerts, failed captures and unanswered cases will remain in the evaluation. Resource cost, diagnosis delay and misleading answers will also be reported.

A bounded feasibility pilot is planned before a separately specified main experiment. Neither has been run. The results are intended to guide the design of performance profilers for projects that must balance monitoring cost, diagnostic accuracy and reliability within the conditions tested.

\noindent\textbf{Keywords:} website performance; browser profiling; delayed diagnosis; original-visit evidence; longitudinal measurement; fault attribution
